# GPU angular primitives — commissioning stage

Optional standalone module for original coarse network mechanics. Four explicit laws share C++ host/device code: signed 2D harmonic, wrapped 2D harmonic, 3D cosine penalty, unsigned 3D harmonic. The 3D laws preserve the distinct bend/lock equations found in network3d.py; they do not turn crosslink labels into calibrated chemistry. Device parity has not yet run.

CPU build on macOS: `clang++ -std=c++17 -O2 -ffp-contract=off -dynamiclib cpu.cpp -o liboxt_cpu.dylib`. Linux: use `-fPIC -shared` and a .so output. Only original source is compiled. GPU compilation uses the reviewed NVIDIA NVRTC library via compile_ptx; no CuPy, PyTorch, CUDA runtime wheel or installer is required by the bindings. A compatible NVIDIA driver is required on the eventual device worker.

Input layout: 12 doubles per angular term: two three-component outward image-resolved arms a,b, stiffness k, rest, sign_a, sign_b, mode, active. Signs are ±1; mode 0 signed2D, 1 wrapped2D, 2 cosine3D, 3 unsigned3D. rest is radians except for cosine mode, where it is a rest cosine. active is exactly 0 or 1; pass alive(edge_a)*alive(edge_b)*alive(lock) as applicable. Branch selection and mask updates belong to the caller. Zero active terms return zero without inspecting masked geometry. Arms with squared length <1e-16 are rejected. The 3D cosine denominator matches network3d's 1e-9 clamp. Differentiability at the clamp boundary is not commissioned.

Outputs: 20 doubles per term: E; forces on (arm-a node, center node, arm-b node), 9 components total; full 3x3 configurational virial W_ij=-a_i*dE/da_j-b_i*dE/db_j; status. Nonzero status or nonfinite E is a hard failure. A force vector alone is not sufficient to accept a state. CSR adjacency encodes 3*term+role, preserving accumulation order without atomic force updates. Global E/virial reduction is fixed order within 256-term tiles and across tiles; same-device deterministic repeats are tested, not bitwise CPU/GPU identity.

`GPU.launch_terms` accepts already allocated device pointers. Other named kernels are oxt_build, oxt_gather, oxt_partial, oxt_total and oxt_dEdF. Device callers can retain coordinates/topology/parameters/buffers across steps; all these calculations then occur on device. Low-level interfaces assume correctly sized buffers and trusted topology. `GPU.evaluate` and `GPU.geometry` are transfer-based commissioning adapters with automatic workspace cleanup. They validate host topology dimensions but are not optimized production loops.

For stress in fixed-x periodic network3d, oxt_dEdF uses supplied image derivatives: dE/dF_ij = (dE/da_i)*image_a_j+(dE/db_i)*image_b_j. Divide by the appropriate reference volume for angular first Piola contribution. Add stretching and tether derivatives separately. Do not substitute the full-arm virial for the fixed-x F derivative away from equilibrium; do not mix Cauchy and first Piola stresses. Crack-jump derivatives require the corresponding jump weights and are not computed by this kernel.

The optional lammps_adapter.CudaAngularController mirrors the commissioned single-rank 2D callback. It retains CPU coordinate sorting/image resolution and host/device transfers. It is not a Kokkos style, distributed implementation or a fully GPU-resident LAMMPS integrator. Keep native angular coefficients zero and run the existing orientation/image postchecks. It is deliberately not wired into the default exporter until device and full-trajectory tests pass. The new 3D FCC solver is also not silently switched to these kernels.

The operator has no integrator, equilibrium solver, stretching, tether, contact, sliding, rupture scheduler or chemistry model. A mask is a numerical gate, not a validated damage law. Successful force/stress parity establishes a numerical component, not physical accuracy or full-workflow equivalence.
